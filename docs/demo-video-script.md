## 分镜脚本

### 【0:00 - 0:20】开场 · 痛点切入

**画面**  
黑屏渐出 → 美甲门店场景（门店照片或网上图片）→ 手机界面滚动美甲图册

**旁白**
> "美甲市场每年消费规模超千亿。但在本地生活平台上，用户面临一个根本矛盾：
> 在手机上挑了半小时，下单后才发现——颜色不对、不适合自己的手型。
> 商家则靠人工盯数据、手动调推荐，效率低、易错失热点。"

**字幕卡**：`痛点：看不见 · 选不准 · 运营慢`

---

### 【0:20 - 0:45】方案亮相 · 系统架构全貌

**画面**  
系统架构动画或截图：C端模块（主推荐 / 试戴 / 相似手型）↔ 后端 ↔ B端 Agent 看板

**旁白**
> "Nails-Agent 给出两个答案。
> 
> **C端**：用户上传一张手图，30 秒内看到任意款式戴在自己手上的效果，
> 并通过手型识别获得「跟你手型相近的人都在选什么」的个性化推荐。
>
> **B端**：一个每 12 小时自动跑一轮的智能运营 Agent，
> 监控款式热度与趋势，自动做推荐调整与候选款式上架决策，
> 并把每一次决策的效果复盘成可复用的运营经验。"

**字幕卡**：`C端 · 试戴即所得` + `B端 · 运营自动化`

---

### 【0:45 - 2:10】C端演示 · 完整用户旅程

> **评审覆盖**：完整性 ✦ 应用效果

#### 场景 1：主推荐页（0:45 - 0:58）

**画面**：主推荐页滚动，50 款美甲卡片，标签（颜色/长度）清晰可见

**旁白**
> "用户打开主页，看到由 Agent 实时维护的推荐列表。
> 每一款都有基于视觉特征提取的颜色标签和长度标签。"

---

#### 场景 2：上传手图 → 手型识别（0:58 - 1:20）

**画面**：点击「上传手图」→ 选择手部照片 → 进度条 → 识别结果卡片

**旁白**
> "用户上传一张手图。
> 系统通过计算机视觉提取手型（细长 / 圆润 / 方正）和肤色（fair / medium / deep），
> 写入 `user_hand_profiles` 表，作为后续个性化推荐的基准。"

**画面叠字**：`hand_shape: slender · skin_tone: medium`

---

#### 场景 3：相似手型推荐（1:20 - 1:35）

**画面**：识别完成后弹出「相似手型的用户都在选」弹窗，展示 6 款推荐

**旁白**
> "识别完成后，系统立即展示「相似手型用户的热门款」——
> 这是区别于普通推荐的核心创新点：
> **不是猜你喜欢，而是找跟你长得像的人在选什么。**"

---

#### 场景 4：一键试戴（1:35 - 2:10）

**画面**：点击某款美甲 → 进入详情页 → 点「试戴」→ Loading 动画（≈20-30秒）→ 试戴结果弹窗

**旁白**
> "点击「试戴」，系统调用 ComfyCloud 的 Nano Banana 2 模型，
> 把用户手图和美甲款式图合并成一张真实效果图。
> 30 秒内，用户看到这款美甲戴在自己手上是什么效果。"

**穿插展示**：3-4 张 `canon_*.png` 试戴成品图（不同风格：奶油色 / 闪粉 / 花朵 / 铬粉）

**旁白续**
> "我们预先生成了 100 张覆盖 5 种手型姿势 × 3 个肤色 × 100 款设计的演示图，
> 每一张都达到了韩系美甲 catalog 级别的图像质量。"

---

### 【2:10 - 3:15】B端演示 · Agent 智能运营闭环

> **评审覆盖**：创新性 ✦ 完整性

#### 场景 5：Agent 看板（2:10 - 2:30）

**画面**：B端看板，展示本轮 heat 数据（款式热度排行 + 趋势折线 + 异常标记）

**旁白**
> "B端 Agent 看板实时展示各款式的热度评分——
> 综合浏览、点击、试戴、收藏四个维度计算 heat score，
> 并自动标记异常（突然下跌的款式、趋势上升但曝光不足的候选）。"

---

#### 场景 6：点击「运行下一轮 Agent」（2:30 - 2:55）

**画面**：点击「运行下一轮」按钮 → Agent 跑动进度条 → 决策结果列表展示

**旁白**
> "点击「运行下一轮」，Agent 用 LangGraph.js 完成完整闭环：
> 聚合热度数据 → 识别机会与异常 → 生成 Findings → 执行决策 → 原子切换推荐快照。
>
> 本轮决策：将两款冷门但标签与当前趋势匹配的候选款上架，
> 同时将一款连续下跌的款式降推。
> 决策依据、执行结果、待复盘窗口——全部落进数据库，等下一轮验收。"

---

#### 场景 7：B端 Chat 自然语言播报（2:55 - 3:15）

**画面**：B端 Chat 界面，展示 Agent 的自动播报段落

**旁白**
> "Agent 不只执行操作，还会生成自然语言播报。
> 运营同学无需看数据，直接读摘要就能知道：这轮发现了什么、做了什么、为什么这样做。"

**画面引用示例文字**（agent_runs.chat_summary 内容示意）：  
> *"本轮识别到 STYLE-032（lilac 渐变）热度增长率 +38%，但当前推荐排名 #31，存在曝光不足机会……已提升至 #12 位置，设置 7 日复盘窗口。"*

---

#### 场景 8：策略记忆（strategy_memories）（可选，若有时间）

**画面**：strategy_memories 表数据或看板中的「经验库」面板

**旁白**
> "每次决策到期复盘后，Agent 把「这个动作效果好/不好，为什么」写入 strategy_memories。
> 下一轮分析时，相同场景下 Agent 会调取这段经验作为决策参考——
> **系统在运营过程中持续学习、持续进化。**"

### 【3:15 - 3:45】技术纵深 · 完整性展示

> **评审覆盖**：完整性 ✦ 创新性

**画面**：DB 架构可视化（ERD 截图或 db:check 表行数输出）→ 技术栈卡片

**旁白**
> "系统底座：21 张 SQLite 数据表，从美甲样式、用户手型档案、行为事件，
> 到 Agent 的 Findings、Decisions、PendingReviews、StrategyMemories，
> 完整覆盖 C端行为闭环和 B端 Agent 闭环，无缝衔接。
>
> 技术选型：Next.js 14 全栈 + LangGraph.js Agent + ComfyCloud Nano Banana 2，
> 用最轻量的部署（本地 pnpm dev + ngrok）实现最完整的功能覆盖。
>
> 数据资产：100 张试戴成品图 100% 生成成功，
> 通过 Roboflow 视觉特征提取管线为 98 款美甲构建结构化特征，
> 涵盖颜色族、主色 RGB、长度比例等，支撑精准推荐和 Agent 分析。"

**字幕卡**：`21 表 · 98 款 · 100 张试戴 · 14 手模 · 0 失败`

### 【3:45 - 4:15】商业价值

> **评审覆盖**：商业价值

**旁白**
> "三个核心商业价值：

>
> 对美团本地生活而言，这套系统可以平移到美发、美睫等所有「戴在身上」的美业品类，
